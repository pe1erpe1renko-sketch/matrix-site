# MATRIX

Сайт-калькулятор матрицы судьбы по дате рождения.

## Запуск

```bash
npm install
npm run dev      # локальный просмотр
npm run build    # сборка
npm test         # тесты движка расчёта
```

## Как устроен разбор

Числа считает только `src/lib/matrixEngine.js`. Ни один компонент ничего
не вычисляет: страница получает готовый результат `calculateMatrix()`
и раскладывает его по блокам.

Что где показывать — решает `src/lib/contentPositions.js`:
12 сфер, 92 вопроса и 25 точек октаграммы с путями к числам.
Компонент `Octagram` берёт точки оттуда же, поэтому число в кружке
и текст в панели всегда про одну позицию.

Разбор устроен как сферы с вопросами, а не как длинные статьи: человек
нажимает на вопрос и получает ответ именно на него. **Доступ считается
по вопросу, а не по сфере** — поле `free: true` открывает вопрос даже
в платной сфере, и в каждой сфере открыт первый. Всего открыто 15 из 92.
Проверяйте `slot.locked`, а не `section.locked`.

Сферы свёрнуты по умолчанию, открыта ровно одна: иначе до последней
сферы пришлось бы листать 92 вопроса. Внутри сферы так же — один ответ
за раз. При раскрытии страница подъезжает к заголовку сферы.

Три соседних числа, которые нельзя путать: `today.dayArcana` меняется
каждые сутки, `today.yearArcana` — **в день рождения**, а не первого
января (личный год привязан к циклу человека, иначе это гороскоп),
`today.arcana` (период жизни) держится 2,5 года. Дату следующей смены
личного года движок отдаёт готовой — `today.yearChangeDate`.

Тексты приходят из `src/lib/contentLayer.js`. Сейчас `CONTENT_MODE = 'stub'`:
показываются пять эталонных текстов и шаблон-заглушка. Числа при этом
настоящие всегда. Для рабочего режима: `CONTENT_MODE = 'live'` плюс ключ
провайдера в `generateText()`.

Что показывает каждая страница — решает `PAGE_VIEWS` в той же карте позиций.
Страницы не собирают списки разделов вручную.

## Личный кабинет

Состояние кабинета — вход, сохранённые матрицы, разговоры — пока живёт
в `localStorage` браузера через `src/lib/devStore.js`. Это заглушка:
чтобы подключить бэкенд, достаточно заменить в ней чтение и запись,
компоненты работают через хуки и об источнике данных не знают.

**ID аккаунта** — буква M и шесть случайных цифр (`M-483726`). Не порядковый
номер регистрации: по нему было бы видно, сколько у сервиса пользователей.
Выдаётся один раз при первом входе любым способом и больше не меняется —
его называют в поддержке и он же стоит в реферальной ссылке.

**Гостевой режим.** Матрицы считаются без регистрации, расчёты запоминаются
в браузере. На `/profil` гость видит приглашение войти и карточки своих
расчётов. При входе они переносятся в аккаунт: открытыми остаются столько,
сколько позволяет тариф, остальные под замком — какие именно оставить
открытыми, выбирает человек.

**Наставник.** `buildMentorContext(matrix, person, plan)` собирает всё, что
наставник должен знать перед ответом: числа матрицы целиком, аркан периода
и сколько до смены, аркан дня и завтрашний, название тарифа. Тариф нужен,
чтобы наставник не обещал недоступного. Переключатель «О ком говорим» меняет
именно этот контекст. Вызов провайдера — заглушка `askMentor()`.

## Мобильная версия

Точки перелома: до 640 — телефон, 641–1024 — планшет, дальше десктоп
(`src/theme/responsive.js`).

Вёрстка на встроенных стилях, а их медиазапросом не перекрыть. Поэтому
работают два приёма:

1. **Переменные CSS для отступов.** Встроенный стиль ссылается на
   `var(--secX)`, а значение переменной меняет медиазапрос в `globalCss.js`.
   Так все секции сужаются на телефоне разом, без правки страниц.
2. **Хук `useIsPhone()` для структурных изменений** — там, где меняется не
   размер, а сама раскладка: форма поднимается над текстом, таблица
   перестраивается, кнопки растягиваются во всю ширину.

Что важно знать при правках:

- **`minmax(0, 1fr)`, а не `1fr`.** Колонка `1fr` не сжимается уже своего
  содержимого: одна лента с горизонтальной прокруткой внутри — и весь экран
  уезжает вбок. Та же причина у `minmax(min(100%, 330px), 1fr)` в сетках.
- **Высота тач-цели — 44 пикселя.** Задаётся классами в `globalCss.js`
  (`.chip`, `.btnGold`, …), потому что во встроенных стилях кнопок
  `min-height` не выставлен и перебивать нечего.
- **Чат считает высоту как `100dvh` минус `--appTop`.** `vh` на iOS не
  учитывает адресную строку, а `--appTop` — высоту мобильной шапки;
  без обоих поле ввода уезжает под клавиатуру.
- **Октаграмма** живёт в квадратной сцене с классом `octaStage`
  (`touch-action: none`). Щипок и перетаскивание считает хук `useZoomPan`,
  масштаб ограничен 1..3. Увеличивается вся схема целиком, поэтому числа
  не наезжают друг на друга ни при каком масштабе.
- **Курсор и параллакс** на тач-устройствах не монтируются вовсе
  (`useIsTouch`), а не прячутся стилями.
- **Меню закреплено через `position: fixed`, а не `sticky`.** Sticky здесь
  не работает: у `body` стоит `overflow-x: hidden` (страховка от
  горизонтальной прокрутки), а это делает body прокручиваемым контейнером
  и ломает прилипание к окну. Содержимое отодвигается через `marginLeft`
  у `S.main` — не забудьте про него, если меняете ширину меню.

## Фоновый звук

Кнопка в правом верхнем углу, звук **выключен по умолчанию**: автозапуск
браузеры блокируют, а на телефоне в транспорте он раздражает. Выбор
запоминается — включил один раз, дальше играет сразу.

Трек кладётся в `public/ambient.mp3` (подробности в `public/ambient.README.txt`).
Пока файла нет, кнопка неактивна и подсказывает «Трек не подключён».
Громкость — `VOLUME` в `src/lib/sound.js`.

## Сцена расчёта

Перед выдачей результата проигрывается сцена на 2,8 секунды: четыре строки
с бегущим индикатором и октаграмма, которая собирается из настоящих чисел
матрицы. Показывается **один раз на набор дат** — какие уже видели,
помнит `src/lib/seenReports.js`. Повторяющееся ожидание перестаёт быть
приёмом и становится задержкой.

## Возврат к разбору

Человек читает разбор, нажимает закрытый вопрос и попадает на тарифы.
Обратной дороги там раньше не было — приходилось вводить дату заново,
и это теряло людей в шаге от оплаты.

Ссылка, уводящая с разбора, кладёт точку возврата в state перехода:

```jsx
<Link to="/tarify" state={backToReport(location, sphereId)}>
```

Страница назначения показывает вверху кнопку «← Вернуться к разбору
13.07.1998» (`BackToReport`). Пришёл из меню — state пустой, кнопки нет.
Адрес возврата содержит раскрытую сферу (`?section=relations`), поэтому
человек попадает ровно туда, где остановился; сферу из адреса раскрывает
`SectionsBlock`. После входа модалка возвращает туда же, в разбор.

Точку возврата разбирает `useResolveBackPoint()` в макете и раздаёт вниз
через контекст — так страница и модалка входа видят одно и то же.
State перехода лежит в записи истории браузера, поэтому кнопка переживает
перезагрузку и «назад».

Посчитанные даты складываются в `src/lib/recent.js` (localStorage, пять
последних, одинаковые даты не двоятся) и показываются строкой «Недавние»
над формой на главной.

## Правило оплаты

**Платят за дату, а не за калькулятор.** Один купленный разбор открывает всё,
что считается по этому набору дат: `/matrica/13-07-1998`, `/finansy/13-07-1998`
и `/prognoz/13-07-1998` открываются одной покупкой.

Другой набор дат — другой разбор и отдельная единица лимита:
детская считается по дате ребёнка, совместимость и бизнес — по двум датам.
Совместимость и бизнес по одной и той же паре дат — **один** разбор:
платят за дату, а не за калькулятор. Порядок дат значения не имеет.

Реализовано в `src/lib/access.js`. Сколько разборов можно держать открытыми —
из `PLAN_LIMITS.matrices`. Сейчас это заглушка на sessionStorage со служебным
переключателем вверху страницы (`DevPlanSwitch`): на предпросмотре можно
открыть разбор и увидеть правило в действии. Когда появятся вход и оплата,
заменить нужно будет только хранилище внутри `access.js`, а переключатель удалить.

Перед изменениями прочитайте `CLAUDE.md`.

## Требование к хостингу

Страницы вида `/matrica/13-07-1998` должны открываться **по прямой ссылке** —
на этом держится поисковый трафик и пересылка ссылок. Файлов с такими именами
на диске нет, страницу собирает приложение в браузере, поэтому хостинг должен
отдавать `index.html` на любой неизвестный адрес вместо ошибки 404.

Правило уже настроено для трёх хостингов, настраивать в панели ничего не нужно:

| Хостинг | Файл с правилом |
|---|---|
| Vercel | `vercel.json` |
| Netlify | `public/_redirects` |
| Cloudflare Pages | `public/_redirects` |

Статические файлы (картинки, собранный код) это правило не ломает: хостинг
сначала ищет настоящий файл и только потом, если не нашёл, отдаёт `index.html`.

На других хостингах то же самое настраивается вручную:
- nginx — `try_files $uri /index.html;`;
- GitHub Pages — копия `index.html` под именем `404.html`.

Проверить просто: откройте `/matrica/13-07-1998` в новой вкладке.
Если видите разбор — настроено верно, если 404 — нет.
