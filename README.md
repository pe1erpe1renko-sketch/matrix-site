# MATRIKA

> Код твоей души

Сайт-калькулятор матрицы судьбы по дате рождения.

## Запуск

```bash
npm install
npm run dev      # локальный просмотр
npm run build    # сборка
npm test         # тесты движка расчёта
```

## Как устроен разбор

Числа считает только `src/lib/matrixEngine.js`. Ни один компонент ничего
не вычисляет: страница получает готовый результат `calculateMatrix()`
и раскладывает его по блокам.

Что где показывать — решает `src/lib/contentPositions.js`:
12 сфер, 92 вопроса и 25 точек октаграммы с путями к числам.
Компонент `Octagram` берёт точки оттуда же, поэтому число в кружке
и текст в панели всегда про одну позицию.

Разбор устроен как сферы с вопросами, а не как длинные статьи: человек
нажимает на вопрос и получает ответ именно на него. **Доступ считается
по вопросу, а не по сфере** — поле `free: true` открывает вопрос даже
в платной сфере, и в каждой сфере открыт первый. Всего открыто 15 из 92.
Проверяйте `slot.locked`, а не `section.locked`.

Сферы свёрнуты по умолчанию, открыта ровно одна: иначе до последней
сферы пришлось бы листать 92 вопроса. Внутри сферы так же — один ответ
за раз. При раскрытии страница подъезжает к заголовку сферы.

Три соседних числа, которые нельзя путать: `today.dayArcana` меняется
каждые сутки, `today.yearArcana` — **в день рождения**, а не первого
января (личный год привязан к циклу человека, иначе это гороскоп),
`today.arcana` (период жизни) держится 2,5 года. Дату следующей смены
личного года движок отдаёт готовой — `today.yearChangeDate`.

Тексты приходят из `src/lib/contentLayer.js`. Сейчас `CONTENT_MODE = 'stub'`:
показываются пять эталонных текстов и шаблон-заглушка. Числа при этом
настоящие всегда. Для рабочего режима: `CONTENT_MODE = 'live'` плюс ключ
провайдера в `generateText()`.

Что показывает каждая страница — решает `PAGE_VIEWS` в той же карте позиций.
Страницы не собирают списки разделов вручную.

## Личный кабинет

Состояние кабинета — вход, сохранённые матрицы, разговоры — пока живёт
в `localStorage` браузера через `src/lib/devStore.js`. Это заглушка:
чтобы подключить бэкенд, достаточно заменить в ней чтение и запись,
компоненты работают через хуки и об источнике данных не знают.

**ID аккаунта** — буква M и шесть случайных цифр (`M-483726`). Не порядковый
номер регистрации: по нему было бы видно, сколько у сервиса пользователей.
Выдаётся один раз при первом входе любым способом и больше не меняется —
его называют в поддержке и он же стоит в реферальной ссылке.

**Гостевой режим.** Матрицы считаются без регистрации, расчёты запоминаются
в браузере. На `/profil` гость видит приглашение войти и карточки своих
расчётов. При входе они переносятся в аккаунт: открытыми остаются столько,
сколько позволяет тариф, остальные под замком — какие именно оставить
открытыми, выбирает человек.

**Наставник.** `buildMentorContext(matrix, person, plan)` собирает всё, что
наставник должен знать перед ответом: числа матрицы целиком, аркан периода
и сколько до смены, аркан дня и завтрашний, название тарифа. Тариф нужен,
чтобы наставник не обещал недоступного. Переключатель «О ком говорим» меняет
именно этот контекст. Вызов провайдера — заглушка `askMentor()`.

## Мобильная версия

Точки перелома: до 640 — телефон, 641–1024 — планшет, дальше десктоп
(`src/theme/responsive.js`).

Вёрстка на встроенных стилях, а их медиазапросом не перекрыть. Поэтому
работают два приёма:

1. **Переменные CSS для отступов.** Встроенный стиль ссылается на
   `var(--secX)`, а значение переменной меняет медиазапрос в `globalCss.js`.
   Так все секции сужаются на телефоне разом, без правки страниц.
2. **Хук `useIsPhone()` для структурных изменений** — там, где меняется не
   размер, а сама раскладка: форма поднимается над текстом, таблица
   перестраивается, кнопки растягиваются во всю ширину.

Что важно знать при правках:

- **`minmax(0, 1fr)`, а не `1fr`.** Колонка `1fr` не сжимается уже своего
  содержимого: одна лента с горизонтальной прокруткой внутри — и весь экран
  уезжает вбок. Та же причина у `minmax(min(100%, 330px), 1fr)` в сетках.
- **Высота тач-цели — 44 пикселя.** Задаётся классами в `globalCss.js`
  (`.chip`, `.btnGold`, …), потому что во встроенных стилях кнопок
  `min-height` не выставлен и перебивать нечего.
- **Чат считает высоту как `100dvh` минус `--appTop`.** `vh` на iOS не
  учитывает адресную строку, а `--appTop` — высоту мобильной шапки;
  без обоих поле ввода уезжает под клавиатуру.
- **Октаграмма** живёт в квадратной сцене с классом `octaStage`
  (`touch-action: none`). Щипок и перетаскивание считает хук `useZoomPan`,
  масштаб ограничен 1..3. Увеличивается вся схема целиком, поэтому числа
  не наезжают друг на друга ни при каком масштабе.
- **Курсор и параллакс** на тач-устройствах не монтируются вовсе
  (`useIsTouch`), а не прячутся стилями.
- **Меню закреплено через `position: fixed`, а не `sticky`.** Sticky здесь
  не работает: у `body` стоит `overflow-x: hidden` (страховка от
  горизонтальной прокрутки), а это делает body прокручиваемым контейнером
  и ломает прилипание к окну. Содержимое отодвигается через `marginLeft`
  у `S.main` — не забудьте про него, если меняете ширину меню.

## Фоновый звук

Кнопка в правом верхнем углу, звук **выключен по умолчанию**: автозапуск
браузеры блокируют, а на телефоне в транспорте он раздражает. Выбор
запоминается — включил один раз, дальше играет сразу.

Трек кладётся в `public/ambient.mp3` (подробности в `public/ambient.README.txt`).
Пока файла нет, кнопка неактивна и подсказывает «Трек не подключён».
Громкость — `VOLUME` в `src/lib/sound.js`.

## Сцена расчёта

Перед выдачей результата проигрывается сцена на 2,8 секунды: четыре строки
с бегущим индикатором и октаграмма, которая собирается из настоящих чисел
матрицы. Показывается **один раз на набор дат** — какие уже видели,
помнит `src/lib/seenReports.js`. Повторяющееся ожидание перестаёт быть
приёмом и становится задержкой.

## Типы разбора

Тип разбора — это НЕ отдельный расчёт, а фильтр: какие из 92 вопросов
показать. Числа считает один и тот же движок, поэтому десять типов стоят
ровно столько же, сколько один.

Список типов лежит в `CALC_TYPES` (`src/lib/contentPositions.js`) и оттуда
расходится сам: карусель в форме, меню, маршруты (`src/routes.js`,
`src/App.jsx`). Добавили тип в `CALC_TYPES` — он появился в карусели
и получил адрес; остаётся дать ему короткую надпись в `SHORT` и набор
текстов в `TABS` на главной.

Страницы результата:

| Компонент | Адреса |
|---|---|
| `MatricaResult` | `/matrica/:date` — вся схема целиком |
| `DengiResult` | `/dengi/:date` — октаграмма с акцентом на денежный канал |
| `DetskayaResult` | `/detskaya/:date` |
| `PrognozResult` | `/prognoz/:date` |
| `TypeResult` | `/karma`, `/zdorovie`, `/rod`, `/prednaznachenie` — отличаются только набором вопросов |
| `PairResult` | `/sovmestimost`, `/mama-rebenok`, `/biznes` — расчёт по двум датам |

Под каждым разбором, кроме самой матрицы, стоит `FullMatrixBlock`:
по этой дате уже посчитано всё, и оплата открывает не только тот тип,
ради которого человек пришёл. Поле `note` у типа показывается плашкой
`TypeNote` вверху страницы — у детской, здоровья и «мамы и ребёнка».

## Иллюстрации арканов

22 файла лежат в `public/arcana/` и называются по номеру с ведущим нулём:
`01.jpeg` … `22.jpeg`. Путь собирает `arcanaImage()` из `contentPositions.js`.
Формат JPEG, пропорции близки к 3:4, текста в файлах нет намеренно —
номер и название рисует сайт.

Показывает их один компонент `components/ArcanaImage.jsx`:

- аркан дня на `/prognoz` — крупно, с номером поверх картинки, `loading="eager"`;
- раскрытый ответ на вопрос в разборе — маленькая карта слева от текста;
- панель точки октаграммы — карта того аркана, на который нажали.

В свёрнутых сферах картинок нет намеренно: двенадцать карт подряд
превращаются в кашу.

**Скругление обязательно.** Рамка на картинках нарисована со скруглёнными
углами, а файл прямоугольный — по углам остаётся белое. Обёртка всегда
обрезает содержимое (`overflow: hidden`), а радиус берётся не меньше
нарисованного: `max(радиус карточек, 4.5%)`. Проценты нужны потому, что
нарисованный радиус растёт вместе с картинкой, а пиксельный — нет.
У двух файлов из двадцати двух вдоль края идёт белая полоска в полпроцента
ширины, поэтому картинка растянута на 102% и сдвинута на процент: внешний
процент уходит под обрезку вместе с полоской.

Соотношение сторон задано жёстко, чтобы страница не прыгала при загрузке.
Если файл не загрузился, на его месте остаётся тот же прямоугольник
с номером аркана — битой иконки человек не увидит.

## Облачко-подсказка

Карточка справа внизу с одной мыслью по матрице человека и переходом
дальше. Живёт в макете, но появляется только там, где страница сама
сообщила о расчёте через `setHintContext()` — на страницах разбора
и на главной с незаполненной формой. Кабинет, чат и тарифы ничего
не сообщают, и подсказки там не бывает.

Правила молчания (`components/HintBubble.jsx`):

- первая — не раньше 90 секунд и только после 10 секунд без прокрутки:
  пока человек листает, он ещё читает;
- следующая — не раньше чем через 5 минут и только если человек за это
  время что-то делал;
- не больше трёх за день, счётчик обнуляется на следующий день;
- показанная подсказка не возвращается никогда: её id уходит в `seen`
  в localStorage. Крестик — то же самое, только раньше.

Что показать, решает `pickHint()`: сначала «долго читает одну сферу»,
потом «только открыл разбор впервые», потом «упёрся в третий замок»,
иначе первая неиспользованная из списка. Числа берутся из уже посчитанной
матрицы; если числа нет — подсказка молча пропускается, «аркан undefined»
на экране быть не должно.

Выключается в профиле, вкладка «Данные», переключателем «Подсказки».
Для проверки на предпросмотре есть `?hint=now` — ожидание пропускается.

## Возврат к разбору

Человек читает разбор, нажимает закрытый вопрос и попадает на тарифы.
Обратной дороги там раньше не было — приходилось вводить дату заново,
и это теряло людей в шаге от оплаты.

Ссылка, уводящая с разбора, кладёт точку возврата в state перехода:

```jsx
<Link to="/tarify" state={backToReport(location, sphereId)}>
```

Страница назначения показывает вверху кнопку «← Вернуться к разбору
13.07.1998» (`BackToReport`). Пришёл из меню — state пустой, кнопки нет.
Адрес возврата содержит раскрытую сферу (`?section=relations`), поэтому
человек попадает ровно туда, где остановился; сферу из адреса раскрывает
`SectionsBlock`. После входа модалка возвращает туда же, в разбор.

Точку возврата разбирает `useResolveBackPoint()` в макете и раздаёт вниз
через контекст — так страница и модалка входа видят одно и то же.
State перехода лежит в записи истории браузера, поэтому кнопка переживает
перезагрузку и «назад».

Посчитанные даты складываются в `src/lib/recent.js` (localStorage, пять
последних, одинаковые даты не двоятся) и показываются строкой «Недавние»
над формой на главной.

## AI-образы

Картинка-талисман по матрице: иллюстрация аркана, подписанная именем
человека. Её ставят на заставку телефона и отправляют близким — это
единственная механика, которая приводит новых людей без затрат на рекламу.

**Нейросеть при нажатии не вызывается.** Образ собирается из готовой
иллюстрации `public/arcana/NN.jpeg` и оформления, нарисованного кодом,
поэтому появляется мгновенно и ничего не стоит. Сцена на две секунды —
оформление ожидания, а не работа.

Семь тем в `lib/images.js`, у каждой своё число из матрицы: ядро, денежный
канал, линия отношений, сексуальная энергия, теневая точка. Совместимость
считает `calculatePair()` по двум датам, подарок — матрицу того, кому дарят.

- `/obrazy` — меню тем, экран темы, сцена сборки, готовый образ;
- «Сохранить картинку» собирает файл 900×1200 на canvas (`lib/imageFile.js`);
- «Поделиться» отдаёт системное меню на телефоне, иначе копирует ссылку;
- `/obraz/{id}` — страница для того, кому переслали: образ и одна кнопка
  «Рассчитать свою матрицу».

Содержимое образа упаковано в сам адрес (`encodeImageId`), поэтому ссылка
работает у человека, которого у нас никогда не было. Когда появится бэкенд,
id станет коротким кодом, а читать его будет та же `decodeImageId`.

**Первый образ бесплатен всем** — это канал привлечения, а не расход.
Дальше работает месячный лимит тарифа (`PLAN_LIMITS.images`), сверх него —
5 молний за образ.

Раздел обязан работать без файлов иллюстраций: вместо картинки рисуется
градиент в цвете темы и крупный номер аркана. Битых картинок быть не должно.

| `pair` | парный разбор, поле `pairKind`: love, business, parentChild |
| `point` | подсказка при клике на точку октаграммы |
| `daily` | аркан дня |
| `year` | личный год, поле `aspect` |
| `image` | текст к AI-образу |
| `mentor` | чат с наставником — единственное место без кэша |

Какой тип просить, решает `lib/pageSections.js`, а не компонент: он
единственный видит, из какого набора пришла сфера. Компонент передаёт
дальше то, что получил.

`PROMPT_VERSION` при правке промпта поднимается: тексты старой версии
помечаются устаревшими и перегенерируются, а не смешиваются с новыми.

В `MENTOR_SYSTEM_PROMPT` есть блок «ЕСЛИ ЧЕЛОВЕКУ ПЛОХО»: при признаках
тяжёлого состояния наставник прекращает трактовки арканов и мягко выводит
на живого специалиста. **Этот блок не сокращать и не переписывать.**

## Единица счёта — разбор

Человек не покупает даты и не считает матрицы: он покупает **разбор**.
Один разбор — одна дата рождения, по ней открываются все двенадцать сфер
и все десять типов. Так и написано везде: в тарифах, в кабинете, на пейволле,
в оформлении и в счётчиках. Поле лимита в `PLAN_LIMITS` называется `reports`,
чтобы код и тексты говорили одинаково.

Слово «матрица» осталось там, где оно про метод и про схему: «матрица
судьбы», «октаграмма вашей матрицы», «матрица посчитана». Как единица
счёта — нигде.

## Молнии

Молнии — валюта только для того, что обращается к нейросети:

```
1 молния  — сообщение наставнику
5 молний  — AI-образ
50 молний — дополнительный разбор сверх тарифа
```

За молнии **никогда** не берут: читать свои разборы, считать матрицу, смотреть
октаграмму, получать аркан дня, скачивать PDF. Это написано на странице тарифов
и в панели баланса: без такой строки люди решают, что за чтение своих же
разборов тоже возьмут, и перестают нажимать кнопки.

Правила интерфейса (`lib/bolts.js`, `components/BoltGate.jsx`):

- цена видна ДО нажатия — на кнопке, значком и числом;
- баланс всегда в шапке, по нажатию — история списаний;
- перед крупным списанием (образ, дата) — подтверждение с остатком;
  на сообщение наставнику подтверждения нет, в переписке оно раздражает;
- когда не хватает, кнопка НЕ блокируется: `spendBolts()` возвращает отказ,
  и открывается окно с недостачей, ценой пакета и тарифом, где молнии входят
  в подписку. Заблокированная кнопка не объясняет ничего.

## Оформление покупки

Три входа, одна страница `/checkout` (`lib/order.js` разбирает адрес):

```
/checkout?plan=circle                      подписка
/checkout?product=matrix&date=13-07-1998   разбор одной даты
/checkout?product=bolts&pack=150           пакет молний
```

Периодов нет: подписка только ежемесячная. Вверху две ссылки назад — к выбору
тарифа и к разбору, — и обе сохраняют введённое (`lib/checkoutDraft.js`,
sessionStorage). Иначе получается тот же тупик, только на шаг позже.

Почта для чека сохраняется в профиль **только после успешной оплаты**.
Кнопка оплаты неактивна без корректной почты и галочки согласия; почему —
говорит подсказка над курсором, а не строка под кнопкой: строка читается
как ошибка, которой ещё не было.

`/checkout/success` — экран после оплаты, свой для каждой покупки: разовый
разбор → сравнение с подпиской, подписка → три первых шага, молнии → новый
баланс. Доступ там выдаётся заглушкой; по-настоящему его выдаёт webhook
платёжной системы, потому что до этого адреса можно дойти по прямой ссылке.

Подключение оплаты — `lib/payment.js`: там подписи функций, что они принимают
и что обязаны вернуть. Главное правило записано там же: суммы и скидки
пересчитываются на сервере заново, фронту верить нельзя.

## Правило оплаты

**Платят за дату, а не за тип разбора.** Один купленный разбор открывает всё,
что считается по этому набору дат: `/matrica/13-07-1998`, `/finansy/13-07-1998`
и `/prognoz/13-07-1998` открываются одной покупкой.

Другой набор дат — другой разбор и отдельная единица лимита:
детская считается по дате ребёнка, совместимость и бизнес — по двум датам.
Совместимость и бизнес по одной и той же паре дат — **один** разбор:
платят за дату, а не за калькулятор. Порядок дат значения не имеет.

Реализовано в `src/lib/access.js`. Сколько разборов можно держать открытыми —
из `PLAN_LIMITS.matrices`. Сейчас это заглушка на sessionStorage со служебным
переключателем вверху страницы (`DevPlanSwitch`): на предпросмотре можно
открыть разбор и увидеть правило в действии. Когда появятся вход и оплата,
заменить нужно будет только хранилище внутри `access.js`, а переключатель удалить.

Перед изменениями прочитайте `CLAUDE.md`.

## Требование к хостингу

Страницы вида `/matrica/13-07-1998` должны открываться **по прямой ссылке** —
на этом держится поисковый трафик и пересылка ссылок. Файлов с такими именами
на диске нет, страницу собирает приложение в браузере, поэтому хостинг должен
отдавать `index.html` на любой неизвестный адрес вместо ошибки 404.

Правило уже настроено для трёх хостингов, настраивать в панели ничего не нужно:

| Хостинг | Файл с правилом |
|---|---|
| Vercel | `vercel.json` |
| Netlify | `public/_redirects` |
| Cloudflare Pages | `public/_redirects` |

Статические файлы (картинки, собранный код) это правило не ломает: хостинг
сначала ищет настоящий файл и только потом, если не нашёл, отдаёт `index.html`.

На других хостингах то же самое настраивается вручную:
- nginx — `try_files $uri /index.html;`;
- GitHub Pages — копия `index.html` под именем `404.html`.

Проверить просто: откройте `/matrica/13-07-1998` в новой вкладке.
Если видите разбор — настроено верно, если 404 — нет.
